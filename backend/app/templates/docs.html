What PulseCheck is

PulseCheck is a dead man's switch for scheduled jobs. You give it a URL; your job pings that URL every time it finishes successfully. If a ping doesn't arrive within the expected window, PulseCheck assumes the job silently failed — didn't run, crashed before finishing, or the machine it lives on died — and emails you.

It watches for the absence of a signal. That's a different job from almost everything else in a typical monitoring stack, which watches for the presence of bad signals (errors, high latency, low disk).

Quick start

  1. Log in and create a monitor — give it a name and how often the job is expected to run.
  2. Copy the ping URL it generates.
  3. Add one line to your job so it hits that URL only when the job succeeds.

That's the whole integration surface. No agent to install, no library to import — just an HTTP request.

Integration examples

Cron (bash)

* * * * * /path/to/backup.sh && curl -fsS https://pulsecheck-shivam.fly.dev/ping/<token>

The && matters — the ping only fires if backup.sh exits 0.

Docker container / entrypoint wrapper

#!/bin/sh
set -e
/app/run-nightly-job.sh
curl -fsS https://pulsecheck-shivam.fly.dev/ping/<token>

Kubernetes CronJob

spec:
  jobTemplate:
    spec:
      template:
        spec:
          containers:
            - name: job
              image: your-image
              command:
                - sh
                - -c
                - "/app/run.sh && curl -fsS https://pulsecheck-shivam.fly.dev/ping/<token>"
          restartPolicy: Never

GitHub Actions

- name: Run scheduled task
  run: ./scripts/nightly.sh

- name: Report success to PulseCheck
  if: success()
  run: curl -fsS https://pulsecheck-shivam.fly.dev/ping/<token>

systemd timer

[Service]
ExecStart=/usr/local/bin/run-job.sh
ExecStartPost=/usr/bin/curl -fsS https://pulsecheck-shivam.fly.dev/ping/<token>

Airflow DAG

def notify_pulsecheck(context):
    import requests
    requests.get("https://pulsecheck-shivam.fly.dev/ping/<token>", timeout=5)

task = PythonOperator(
    task_id="nightly_job",
    python_callable=run_job,
    on_success_callback=notify_pulsecheck,
)

How this fits next to Prometheus + Grafana

If you're already running Prometheus and Grafana, PulseCheck isn't a replacement — it's covering a blind spot those tools have by design.

Prometheus + GrafanaPulseCheck
ModelPull — scrapes metrics from running servicesPush — your job reports in when it finishes
Best forLong-running services: request rate, latency, error rate, resource usageOne-shot / scheduled jobs: cron, backups, batch scripts, CI jobs
Fails to catchA cron job that never starts — there's no running process to scrapeGradual performance decay in a live service — that's what Prometheus is for
SetupExporter + scrape config + alert rulesOne curl call at the end of your job

There's a Prometheus-compatible /metrics endpoint, scoped to your account with a token — find your URL and an example scrape config on your account settings page.

Prometheus / Grafana metrics

Every account has its own scrape endpoint at /metrics/<your-token> (grab the exact URL from account settings — it's scoped to you, so treat it as a secret). It exposes:

  • pulsecheck_monitor_up — 1 or 0, per monitor
  • pulsecheck_monitor_last_ping_timestamp_seconds — unix timestamp of the last ping
  • pulsecheck_monitor_seconds_since_last_ping — how long it's been quiet
  • pulsecheck_monitor_period_seconds — the expected interval, for context
  • pulsecheck_monitors_total{status="..."} — counts by status

Point an existing Prometheus at it and the monitors show up on a Grafana dashboard next to everything else you already watch — no separate tool to check.

FAQ

What if my job fails partway through?
If the ping is the last line of your script, a failure earlier means no ping is sent, and PulseCheck alerts you when the window passes — exactly the case you care about.

What if my job legitimately takes longer some days?
Set the grace period generously. It's the buffer added on top of the expected interval before an alert fires.

Do I need to install anything on my server?
No. A ping is one HTTP request — curl, wget, or any HTTP client works.
